# AGENTS.md: KanbanVibe Frontend

Этот репозиторий использует OpenCode и Spec Kit. Агенты обязаны прочитать этот файл перед началом работы. Проект: KanbanVibe — профессиональный frontend (Vue 3 SPA), а не учебный прототип. Источник норм — `.specify/memory/constitution.md` (v2.1.0): расширяемость, надёжность, функциональность. Язык артефактов — русский.

## Правила Проекта

- Нормы качества задаёт конституция. «Минимальный diff», YAGNI и «достаточно для занятия» не отменяют тесты критического пути, screenshot-тесты, явную ошибку и версию контракта.
- Все артефакты (docs, specs, ADR) — на русском языке.
- Опубликованный контракт не ломайте молча. Несовместимое изменение — только через версию контракта и ADR.
- Не коммитьте изменения без явной просьбы.
- Комментарии в коде — только там, где это экономит время чтения.
- Фиксируйте результаты (изменённые файлы, команды, вывод) в сессии.

## Ветки

Модель: `main` ← `development/v1.0.0` ← `feature/*`. Сейчас рабочая ветка фичи — `feature/auth`. Ветка `development/v1.0.0` ведёт линию версии 1.0.0.

- `development/v1.0.0` ответвлять от `main`.
- Новую `feature/*` ответвлять от `development/v1.0.0`.
- Ветку задачи ответвлять от текущей `feature/*` (`feature/auth`), не от `main` и не от `development/v1.0.0`.
- PR агента открывать с base = текущая `feature/*` (сейчас `feature/auth`). В `main` и в `development/*` напрямую не открывать.

Продвижение фичи: ветка задачи → `feature/*` → `development/v1.0.0` → `main`. Каждый шаг — отдельный PR.

## Версии и теги

- Релиз — это git-тег `vMAJOR.MINOR.PATCH`. Тег `v1.0.0` соответствует ветке `development/v1.0.0`.
- Тег ставит тот, кто выпускает релиз, на коммите `main` после merge `development/v1.0.0` → `main`. Пока версия не выпущена, тег не создавать (настройка CI релизом не является).
- `main` не переписывать через force-push.

## Spec-Driven Workflow (Spec Kit)

Источник истины по процессу — `.specify/memory/constitution.md`. Команды Spec Kit — `/speckit.*`.

Основной цикл для новой функциональности:

1. `/speckit.constitution` — зафиксировать/обновить принципы проекта.
2. `/speckit.specify` — создать спецификацию в `specs/NNN-feature-name/spec.md`.
3. `/speckit.clarify` — устранить неоднозначности до планирования.
4. `/speckit.plan` — получить `specs/NNN-feature-name/plan.md` с Constitution Check по принципам I–V.
5. `/speckit.tasks` — получить `specs/NNN-feature-name/tasks.md`.
6. `/speckit.implement` — реализовать задачи по порядку.
7. `/speckit.analyze`, `/speckit.checklist` — проверить согласованность артефактов.

Правила:

- Не начинайте реализацию фичи без `spec.md` и `tasks.md`; мелкие исправления и документацию можно делать напрямую, если поведение и контракт не меняются.
- Изменения кода должны соответствовать `plan.md` и задачам из `tasks.md`.
- При изменении поведения обновляйте спецификацию фичи и опубликованный контракт. ADR обновляйте вместе с ними, если для правила он есть.
- Объём фазы фиксирует спецификация. Дорожная карта задаёт направление и не снижает планку конституции.

## Skills как инструменты

## Стек и Команды

- Frontend: Vue 3, Vite, TypeScript, Pinia. Приложение в корне репозитория kanbanVibe-front, не в каталоге `frontend/`.
- Backend живёт в репозитории kanbanVibe-Back (веб-API .NET). Не создавайте backend в этом репозитории.
- Сборка закрепляет kanbanVibe-Back на git-теге `v0.0.0`: `npm ci` и `npm run build` забирают этот тег (`package.json` → `kanbanVibeBackend`, `scripts/fetch-backend-tag.mjs`).
- Базовый URL API: переменная `VITE_API_BASE_URL` (пример — `.env.example`).
- Установка: `npm ci`.
- Сборка: `npm run build`.
- Локальный запуск: `npm run dev`.
- Просмотр сборки: `npm run preview`.
- В `package.json` нет скриптов `lint` и `test`. Не вызывайте их, пока скрипт не появится.
- CI: `.github/workflows/ci.yml` — `npm ci` и `npm run build` на Node.js 22 на каждый push и pull request. Ненулевой код любой из команд роняет job.
- CD в этом репозитории нет: ни workflow публикации, ни GitHub Release, ни артефактов релиза. Push в `main` и тег релиза сами по себе ничего не публикуют.

- Спецификации фич: `specs/NNN-feature-name/` (`spec.md`, `plan.md`, `tasks.md`)
- Черновик контракта: `specs/002-frontend-dev/contracts/api.yaml`

## Минимальный Контекст

- Основные сущности: Board, Column, Card. Инварианты — в конституции, принцип IV.
- Целевая модель доступа: учётная запись, JWT, своя доска пользователя. Анонимная запись доски — переходное состояние, не норма.
- Компонент не вызывает сеть и не читает токен из хранилища браузера. Единственная сетевая граница — `src/services`.
- `npm run build` должен проходить. Ошибку типов ради сборки не подавлять.
