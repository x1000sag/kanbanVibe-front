# Data Model: Своя доска

**Feature**: 003-account-board-screen
**Date**: 2026-11-25

Имена полей JSON совпадают с [contracts/account-board.yaml](contracts/account-board.yaml). Это подмножество опубликованного `/v1`, а не PascalCase старого клиента и не `data/board.json`. Правила валидации, которые сервер уже навязывает, подмена повторяет. Правила только экрана помечены отдельно.

## Учётная запись

Один человек. Владеет ровно одной доской.

| Поле | Тип | Обязательное | Правило |
|---|---|---|---|
| nick | string | да | Уникален. Сравнение точное по регистру. Краевые пробелы сняты до записи, внутренние сохранены. Длина 1–64 скаляра Unicode. Пустое и более длинное отвергается целиком, без обрезки |
| displayName | string | да | При создании равно `nick`. Дальше меняется отдельно. После снятия краевых пробелов 1–128 скаляров. Уникальным быть не обязано |
| passwordVerifier | bytes | да | Только внутри подмены. SHA-256 UTF-8. На экран, в store и в JSON не выходит. Открытый пароль не хранится |

Пароль на входе: 1–1024 скаляра, без обрезки, пробелы значимы, совпадение с логином допустимо. Пароль из одних пробелов не пустой.

## Сессия

Не сущность экрана. Живёт в порте.

| Поле | Тип | Правило |
|---|---|---|
| accessToken | string | Непрозрачный. Не пароль. Не читается компонентом |
| expiresAt | date-time UTC | Не позже выдачи плюс 12 часов. Выдача усечена до целой секунды UTC |
| nick | string | Ник предъявленного доступа |

Второй успешный вход того же ника не отзывает прежний токен. Экран помнит только тот токен, который получил последним. Выход гасит только его. Истечение и `no_active_access` не удаляют учётку и доску.

## Доска

Имени нет. На учётки приходится одна.

| Поле | Тип | Обязательное | Правило |
|---|---|---|---|
| columns | Column[] | да | Порядок по позиции создания: `ToDo`, `InProgress`, `Done` |

Человек не добавляет, не удаляет и не переименовывает колонки с этого экрана.

## Колонка

| Поле | JSON | На экране | Правило |
|---|---|---|---|
| name | `ToDo`, `InProgress` или `Done` | `To Do`, `In Progress` или `Done` | Имя уникально на доске. В запрос карточки уходит JSON-имя |

Пустая колонка на экране показывает «Пусто». Это не поле JSON.

## Карточка

| Поле | Тип | Обязательное | Правило |
|---|---|---|---|
| id | uuid | да | Уникален. Задаёт подмена |
| title | string | да | Для экрана строка из одних пробелов пустая и не отправляется. Серверное `card_invalid` — пустая строка |
| description | string или null | нет | Пустое поле уходит как `null`. На карточке строки описания тогда нет |
| tags | string[] | да | Этот экран пишет один элемент. Пустая метка и повтор без учёта регистра — `card_invalid`. Чужие несколько меток, если придут в ответе, не раскладываются: видна первая |
| deadline | string или null | нет | `YYYY-MM-DD` или `null`. Иной вид — `card_invalid` |
| createdAt | date-time UTC | да | До целой секунды. На экране отдельно не пишется |

Карточка принадлежит одной колонке. Поля уже созданной карточки этот контракт не переписывает: операции изменения нет. Удаление убирает карточку без второго подтверждения.

Порядок внутри колонки — по возрастанию `createdAt`, затем по `id`. Отдельного поля позиции нет. Перетаскивание порядок и колонку не меняет.

## Категория

Не поле сервера. Это один элемент `tags` и метка на карточке.

Готовые написания: `UX Design`, `UI Design`, `Testing`, `Project Management`. Своё написание — до 32 скаляров Unicode включительно. Совпадение без учёта регистра с готовым или уже лежащим на доске именем выбирает уже известное написание, вторую категорию не создаёт. Длиннее 32 на доску не попадает. Это правило экрана, не код `card_invalid`.

## Отказ

| Поле | Тип | Правило |
|---|---|---|
| code | string | Единственное поле тела. Набор — в контракте |

Тело отказа не содержит фразу, пароль, хэш и токен. Фразу выбирает экран по таблице в [contracts/screen.md](contracts/screen.md).

Класс для вызывающей стороны:

| Класс | Когда |
|---|---|
| сеть | Вызов подмены оборвался, кода нет |
| 4xx | Код запроса, входа, валидации, чужих данных, пропавшей карточки |
| отказ доступа | `no_active_access` или местные 12 часов истекли |
| 5xx данные | `store_unavailable` |
| 5xx служба | Иной отказ службы |

Лимит тела, который повторяет подмена: 16 КиБ UTF-8 на один запрос. Сверх него — `request_invalid`.

## Связи

- Учётная запись 1 — 1 доска.
- Доска 1 — 3 колонки в фиксированном порядке.
- Колонка 1 — N карточек.
- Карточка 1 — 1 видимая категория (`tags` из одного элемента для записей этого экрана).
- Учётная запись 1 — N сессий на стороне подмены. Экран держит одну.

Чужая доска и чужое имя через этот порт не читаются и не меняются. Запрос с ником не из текущего токена — `foreign_data`, без тела чужих данных.

## Переходы

### Сессия

1. Нет токена. Экран — гость. Колонок нет.
2. Создание: учётка, затем сессия, затем имя, затем профиль. Успех — внутри, на метке имя. Отказ имени после уже созданной учётки — внутри, на метке логин, фраза про имя, доска этой учётки на месте.
3. Вход: сессия, затем профиль. Профиль не прочитан — колонки успеха не рисуются.
4. Касание после 12 часов или `no_active_access` — токен забыт, карточки с экрана уходят, снова гость и «Нужно войти снова». Учётка в подмене остаётся.
5. Выход — гасится текущий токен, экран гостя, без фразы ошибки. Учётка и доска остаются.

### Карточка

1. Доска этого входа уже показана.
2. Создание принято — карточка в выбранной колонке, окно закрыто, «Пусто» этой колонки скрыто.
3. Создание отклонено — окна не закрывать, на доске нет частичной карточки, последняя показанная доска на месте.
4. Удаление принято — карточки нет. Если колонка опустела, в ней «Пусто».
5. Удаление при уже отсутствующей карточке — «Карточки уже нет», прежний текст карточки не возвращать.
6. `store_unavailable` или обрыв на создании или удалении — последняя успешно показанная доска остаётся. Пустые колонки её не заменяют.

### Имя и пароль в одном сохранении

1. Повтор нового пароля не совпал — запрос не уходит, «Пароли не совпадают». Имя не меняется.
2. Смена пароля отклонена — имя этим сохранением не отправляется.
3. Пароль уже сменён, имя затем отклонено — фраза про имя, на метке прежнее имя, новый пароль уже действует, текущий токен жив.
4. Успех обоих или только имени — метка и заголовок профиля показывают новое имя. Логин прежний.

Два одновременных создания одного нового ника оставляют одну учётку. Второе получает `nick_taken`. Подмена проводит создания по очереди.
