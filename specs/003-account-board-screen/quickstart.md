# Quickstart: Своя доска

**Feature**: 003-account-board-screen
**Date**: 2026-11-25

Проверка реализации этого плана. `npm test` поднимает экран со стендом в памяти и не открывает сокет к API. `npm run dev` вызывает опубликованный `/v1` kanbanVibe-Back. Сборка закрепляет git-тег `v1.0.0`. Поля и коды — [contracts/account-board.yaml](contracts/account-board.yaml). Вид и фразы — [contracts/screen.md](contracts/screen.md). Сущности — [data-model.md](data-model.md).

Команда `npm test` появляется вместе с реализацией. Пока её нет, этот файл — сценарий проверки, а не уже собранный раннер.

## Предварительные требования

- Node.js 22 и npm.
- Репозиторий kanbanVibe-front, каталог приложения — корень, не `frontend/`.
- Для `npm test` сеть к API не требуется: Playwright ставит `VITE_ACCOUNT_BOARD_STANDIN=memory`.
- Для `npm run dev` нужен Kanban.Api тега `v1.0.0` на адресе `VITE_API_BASE_URL` (без переменной — `http://localhost:5050`).
- `npm ci` и `npm run build` забирают git-тег `v1.0.0` kanbanVibe-Back. Если репозиторий закрыт, нужен `BACKEND_SSH_DEPLOY_KEY`.

## Подготовка

```bash
npm ci
npx playwright install --with-deps chromium
```

Адрес в `.env.example` остаётся `http://localhost:5050`. Автоматическая проверка его не вызывает.

## Команды

```bash
npm run build
npm test
npm run dev
```

`npm run build` заканчивается нулём. `npm test` запускает только Playwright: критический путь, клавиатуру, форму контракта и снимки. Второй раннер не ставится.

Ручной просмотр живого API — `npm run dev`, обычно `http://localhost:5173`. Сценарии `npm test` идут против стенда в одной вкладке без перезагрузки, если не сказано иное. Обрыв и конец доступа в автоматической проверке задаёт шов стенда, не отдельный маршрут.

## Сценарии

### 1. Гость

Открыть приложение.

Ожидание: тёплое полотно на весь экран, плитка, слово Board, круглая кнопка, «Войти», текст «Войдите, чтобы открыть свою доску». Колонок нет. Тёмного поля вокруг нет. Кнопка добавления открывает вход и не создаёт карточку.

### 2. Своя пустая доска

Создать учётку: имя «Марина», логин `marina`, пароль. Войти вторым человеком с другим логином.

Ожидание первого: на месте «Войти» буква «М» и имя «Марина», колонки To Do, In Progress, Done, в каждой «Пусто». Пароля на экране нет. Второй человек карточек «Марины» не видит. Исход совпадает с созданием, входом и чтением профиля из контракта, включая имя отдельным шагом после создания.

### 3. Карточка

Войти в пустую доску. Добавить в In Progress карточку «Design homepage mockup» с описанием, категорией UI Design и датой. Отдельно подтвердить окно с пустым названием. Отдельно ввести категорию `Research` и категорию длиннее 32 символов.

Ожидание: карточка видна в In Progress с меткой, названием, описанием, Edit и датой вида `8 Jul`, подписи «Пусто» в этой колонке нет. Пустое название даёт «Нужно название», доска не меняется. `Research` — одна своя метка, не готовая. Длинная категория не добавляется, фраза «Категория не длиннее 32 символов». В теле создания одно значение `tags` и колонка `InProgress`, как в контракте.

### 4. Просмотр и удаление

Открыть единственную карточку To Do. Удалить её. Открыть другую и убедиться, что поля нельзя сохранить заново.

Ожидание: у открытой карточки нет «Сохранить». После удаления карточки нет, в колонке «Пусто». Более ранняя карточка в колонке стоит выше. Перетаскивания нет. Повторное удаление уже исчезнувшей карточки даёт «Карточки уже нет».

### 5. Имя, пароль, выход

Открыть профиль. Сменить имя на «Марина К.» без смены пароля. Отдельно сменить пароль с верным текущим и совпавшим повтором. Выйти и войти новым паролем. Старым войти ещё раз.

Ожидание: логин остаётся `marina`. После выхода видны «Войти» и приглашение, карточек на полотне нет. Новый пароль входит, старый показывает «Не удалось войти». Несовпавший повтор даёт «Пароли не совпадают» и запрос не отправляет. Если смена пароля отклонена, имя этим сохранением не меняется.

### 6. Отказ не похож на пустую доску

Попросить вход с неверным паролем существующей учётки и с несуществующим логином. Затем на уже показанной доске оборвать подмену и попытаться создать или удалить карточку. Отдельно дождаться конца 12 часов или погасить доступ и снова тронуть доску.

Ожидание: обе неудачные пары показывают только «Не удалось войти», пароля в тексте нет. При обрыве карточки остаются, видна фраза «Нет соединения» либо «Данные сейчас недоступны», пустые колонки доску не заменяют. После конца доступа карточки уходят, снова приглашение и «Нужно войти снова».

### 7. Клавиатура и смысл не только цветом

С фокуса на «Войти» открыть окно и нажать Escape. Затем с клавиатуры создать карточку.

Ожидание: после Escape фокус снова на «Войти». Карточка создаётся без указателя. Имя колонки, название категории и текст ошибки читаются словами.

### 8. Снимки

`npm test` сравнивает снимки в репозитории: гость, пустые колонки, доска с карточкой, недоступные данные при ещё видимых карточках, четыре окна (создание, открытая карточка, вход, профиль), ширина полотна меньше 720px. Наблюдатель отличает недоступность данных и от пустой колонки, и от заполненной доски.

## Что не проверяется здесь

Журнал, удаление колонки, перенос карточки и правка уже сохранённых полей. `npm test` не поднимает PostgreSQL и не ходит в тег: тег проверяет сборка, живой вызов проверяет адаптер на подставленном `fetch`.
