## Summary

Вошедший человек видит одну свою доску с макета: тёплое полотно на весь экран, верхняя полоса, три колонки, карточка и четыре окна. Гость видит приглашение, а не чужие карточки.

Экран говорит с уже опубликованным API учётки на ветке `feature/auth` репозитория kanbanVibe-Back через порт той же формы. В этой поставке порт исполняет одна подмена в памяти страницы. Живого сервиса нет. Git-тег `v1.0.0` бэкенда не нужен и не является зависимостью. Новой серверной модели нет.

Исследование — [research.md](research.md). Модель — [data-model.md](data-model.md). Контракт клиента — [contracts/account-board.yaml](contracts/account-board.yaml), экран — [contracts/screen.md](contracts/screen.md). Проверка — [quickstart.md](quickstart.md).

## Technical Context

**Language/Version**: TypeScript 6, Vue 3.5

**Primary Dependencies**: Vue 3, Vite, Pinia, `@fontsource/newsreader`, `@fontsource/dm-sans`. Раннер тестов и снимков — `@playwright/test`.

**Storage**: Подмена в памяти вкладки. Не `localStorage`, не `data/board.json`, не PostgreSQL. Пароль после проверки не хранится. Токен сессии не покидает модуль порта.

**Testing**: Playwright — единственный раннер. Им же screenshot-тесты. Vitest и второй раннер снимков не добавляются.

**Target Platform**: Браузер. Сборка и CI — Node.js 22. Приложение в корне репозитория.

**Project Type**: Web application (Vue SPA)

**Performance Goals**: Создание учётки и появление трёх пустых колонок укладываются в 2 минуты человека (SC-001). Карточка с названием — в 1 минуту (SC-002). Смена экрана 180–220 мс. Отдельной цели по пропускной способности нет.

**Constraints**: Живой HTTP не вызывается. Контракт — подмножество `/v1` с ветки `feature/auth`, OpenAPI `info.version` `1.0.0`, не git-тег `v1.0.0`. Анонимная запись `/api/board` с экрана уходит. Запись доски только после успешного чтения профиля в этом входе. `npm run build` обязан проходить.

**Scale/Scope**: Один экран, одна учётка на сессию экрана, одна доска, три колонки. Подмена помнит учётки до закрытия вкладки.

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Конституция `.specify/memory/constitution.md`, версия 2.1.0. Текст конституции этой командой не менялся.

### До Phase 0

- **I. Расширяемость.** Сеть и токен остаются за `src/services`. Компонент их не касается. Форма запросов — уже опубликованный `/v1`, без нового серверного поля и без анонимной записи как нормы. Флаг живого сервиса не нужен: эта поставка его не включает, точка включения — порт.
- **II. Надёжность.** В репозитории нет npm-раннера. Первый раннер критического пути — Playwright. Screenshot-тесты идут тем же раннером. Второй раннер только ради снимков не добавляется. Отказ виден и различается: сеть, 4xx, 5xx, отказ доступа. Недоступность не выглядит как пустая доска. Пароль на клиенте не сохраняется. Секрет не попадает в репозиторий и в лог.
- **III. Функциональность.** План покрывает спецификацию целиком: гость, пустые колонки, карточка, профиль, клавиатура, отказы. Фразы русские и без пароля. Контракт, конфигурация и вход описаны для интегратора.
- **IV. Консистентность доменной модели.** Board, Column, Card. Имена JSON совпадают с опубликованным контрактом учётки. Одна видимая категория — один элемент `tags`. Срок — `YYYY-MM-DD`, время создания — UTC. Подписи колонок на экране не подменяют хранимые имена.
- **V. Spec-Driven Development.** Constitution Check стоит до проектирования и повторяется после него. `tasks.md` и код приложения эта команда не создаёт.

Ворота до Phase 0 пройдены. Необоснованного нарушения нет.

### После Phase 1

Повторная проверка по принципам I–V против [research.md](research.md), [data-model.md](data-model.md), [contracts/](contracts/) и [quickstart.md](quickstart.md).

- Порт повторяет опубликованные операции и коды. Подмена — единственная реализация. Модуля `fetch` в этой поставке нет.
- Контракт фичи не правит `account-api.yaml` бэкенда и не объявляет анонимное исключение: потребляемый API уже требует доступ.
- Критический путь, защита единственного экрана без сессии и 401 описаны как сценарии Playwright. Снимки: гость, пустые колонки, доска с карточкой, недоступные данные, четыре окна, ширина полотна меньше 720px. Раннер по-прежнему один.
- Запись карточки идёт только после показанной доски этого входа. Сбой оставляет последний успешный показ.
- Запасной адрес `http://localhost:5000` из старого клиента на экран не переносится. `.env.example` остаётся `http://localhost:5050` и этой поставкой для запросов не читается.
- Тестовый шов отказа не входит в продуктовую сборку и не рисует панель макета.

Нового нарушения нет.
